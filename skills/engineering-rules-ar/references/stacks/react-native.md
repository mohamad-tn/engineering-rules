# React Native وExpo

المحرك: محرك Node مع بوابتين للموبايل. اكتشاف الإطار: وجود `expo` أو `react-native`.

| البوابة | ما تشغّله |
|---|---|
| `secrets-files` | الأداة `check-tracked-secrets.mjs`: تفشل عند رفع ملف مفاتيح توقيع (keystore) أو ملف اعتماد أو مفتاح خاص، أو كلمة سر توقيع مكتوبة، أو رابط `http://` بدون تشفير (العناوين المحلية مسموحة) |
| `expo-export` | `expo export --platform android` (لـ Expo فقط): يجب أن تُبنى حزمة الإصدار |

تنطبق كل بوابات Node (انظر [node.md](node.md)).

## الإعداد الموصى به

- مواد التوقيع تعيش في مخزن أسرار أو في خدمة البناء. لا تدخل Git أبدًا.
- إعدادات البيئة (نطاق الواجهة، تثبيت الشهادات) تأتي من متغيرات بيئة وليس من المستودع.
- ابنِ نسخ الاختبار القابلة للتثبيت عند الطلب وانشر معها SHA-256 (workflow يدوي `workflow_dispatch`؛ واحتفظ ببنّاء بديل موثّق لعندما تتعطل خدمة البناء أو تنتهي حصتها).
- فحوص قبل النشر: لا تسجيل في الـ console، ولا قائمة مطوّر، ولا اتصال بدون تشفير، وتثبيت الشهادات موجود.

## التكامل المستمر (CI)

الملف `templates/stacks/react-native/ci.yml`. البناء الأصلي (`APK` أو `IPA`) ليس جزءًا من البوابات الافتراضية لأنه يحتاج حزم المنصات والتوقيع؛ أضفه كـ workflow منفصل يُشغَّل يدويًا.
