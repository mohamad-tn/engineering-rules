# الإثبات المحلي: تشغيل البوابات بدون CI مدفوع

البوابات سكربتات عادية، والـ CI فقط يستدعيها. إذن كل ما يفحصه الـ CI يمكن فحصه على جهاز المطوّر ثم لصق النتيجة في طلب الدمج. استخدم هذا عندما يكون الـ CI المستضاف متوقفًا (انتهت الدقائق، أو عطل، أو لا توجد خطة مدفوعة)، أو قبل الدفع ببساطة.

## أمر واحد

من جذر المستودع، بعد حفظ العمل في commit:

<div dir="ltr">

```bash
bash .github/scripts/local-proof.sh --title "feat: my change"
```

</div>

يشغّل فحص الأسرار، وفحص الوثائق، وبوابات السياسة، وانتهاء الأعلام، وحجم الطلب، **وبوابات التقنية** لكل تقنية يكتشفها، و(إن وُجد الملف) فحص أداة التحديث. ثم يطبع كتلة Markdown فيها الـ commit والتاريخ وصف نجاح أو فشل لكل بوابة. الخيارات:

| الخيار | المعنى |
|---|---|
| `--base <sha>` | الـ commit الأساس؛ الافتراضي هو أقدم سلف مشترك مع `origin/main` |
| `--title "<text>"` | عنوان طلب الدمج الذي تقرؤه قاعدة سجل التغييرات؛ الافتراضي هو عنوان آخر commit |
| `--label <name>` | وسم يحمله الطلب (يمكن تكراره)، مثل `no-docs-needed` |
| `--fast` | يتخطى البناء والتدقيق في بوابات التقنية (لحلقة سريعة أثناء الكتابة؛ شغّله بدونه قبل طلب المراجعة) |
| `--no-stack` | يتخطى بوابات التقنية ويكتب ذلك في الإثبات |
| `--allow-missing` | لا يفشل عند غياب أداة؛ وتبقى البوابة معروضة كـ `NOT RUN` |
| `--out <file>` | يكتب الكتلة أيضًا في ملف |
| `--json` | JSON على stdout؛ وMarkdown على stderr أو في `--out` |

حالة الخروج 0 عندما لا تفشل بوابة ولا توجد بوابة لم تعمل؛ لكن `--allow-missing` يرخّي حالة الخروج فقط ولا يحوّل `NOT RUN` أو `SKIPPED` إلى نجاح. يبقى `ok: false` في JSON عند وجود نتيجة غير مكتملة، ويجب ذكر ذلك في طلب الدمج. حالة `N/A` تعني أن الفحص لا ينطبق، مثل عدم اكتشاف تقنية مدعومة.

قد يخرج `--fast` بالرمز 0 لحلقة التطوير مع صف تقنية `SKIPPED` لأن البناء والتدقيق لم يعملا. يفصل JSON بين `execution_ok` و`proof_complete`؛ والحقل `ok` مطابق لـ `proof_complete` وليس نجاح الأوامر فقط. يبيّن `stack_mode` النمط `full` أو `fast` أو `skipped`. تشغيل fast على تقنية مكتشفة ليس إثباتًا كاملًا؛ أعد التشغيل بدونه قبل المراجعة. الحقول تلخّص البوابات العليا المهيأة، ولا تثبت تشغيل كل فحص أمني ممكن أو بوابة تقنية اختيارية.

## تشغيل بوابة واحدة

| البوابة | الأمر |
|---|---|
| فحص الأسرار | `bash .github/scripts/gitleaks-scan.sh .gitleaks.toml` |
| فحص الوثائق | `bash .github/scripts/docs-check.sh .` (اضبط `BASE_SHA` و`HEAD_SHA` و`PR_TITLE` و`PR_LABELS_JSON` لتطبيق قواعد الطلب) |
| إعداد أداة التحديث | `bash .github/scripts/renovate-config-check.sh .` |
| بوابات السياسة | `node .github/scripts/policy-gates.mjs .` |
| انتهاء الأعلام | `node .github/scripts/feature-flag-expiry.mjs .` |
| حجم الطلب | `BASE_SHA=<sha> HEAD_SHA=<sha> bash .github/scripts/pr-size-check.sh` (بدون متغيرات يستخدم `origin/main...HEAD`) |
| بوابات التقنية | `bash .github/scripts/stack-gates.sh` (الخيار `--fast` يتخطى البناء والتدقيق، والخيار `--list` يعرض ما اكتشفه) |

إصدارات الأدوات ومجاميعها (checksums) مثبّتة في `.github/tool-pins.env`. الأداة الموجودة في `PATH` تُستخدم كما هي؛ وإلا يُنزَّل الإصدار المثبّت ويُتحقق من SHA-256 له (Linux x64). على macOS أو Windows ثبّت `gitleaks` و`lychee` بمدير الحزم.

## إعادة تشغيل ملفات الـ workflow الحقيقية

عندما تحتاج تشغيل ملفات الـ workflow نفسها، يعيد `scripts/ci-local.sh` تشغيلها على جهازك بواسطة `act` في وضع المضيف (host mode)، ويمكنه نشر حالات `ci-local/*` على الـ commit. هذا هو المستوى 2 أو 3 في [`continuity.md`](continuity.md).

## ماذا يفعل المراجع بالإثبات المحلي

1. يتأكد أن الـ commit في الإثبات هو نفسه رأس طلب الدمج.
2. يتأكد أن كل الصفوف ناجحة ولا يوجد `NOT RUN`.
3. في أي شيء خطِر، يعيد تشغيل الأمر الواحد على جهازه.

عندما يعود الـ CI المستضاف، أعد تشغيله على الطلب نفسه. الإثبات المحلي بديل مؤقت وليس استبدالًا.
