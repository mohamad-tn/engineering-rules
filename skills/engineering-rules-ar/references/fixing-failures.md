# إصلاح الإخفاقات

ماذا تفعل عندما تفشل بوابة. اقرأ الرسالة أولًا: كل بوابة تطبع الملف أو القاعدة أو الأمر الذي فشل. ولا «تُصلح» فشلًا أبدًا بتخفيف البوابة.

## البوابات الأساسية

| البوابة والرسالة | السبب | الإصلاح |
|---|---|---|
| فحص الأسرار: `project-dotenv-file` أو `project-signing-key-file` أو قاعدة `gitleaks` افتراضية | سر أو ملف يشبه الأسرار في تاريخ Git | **غيّر السر أولًا.** إذا لم يُشارَك الفرع بعد فأعد كتابته ليختفي الـ commit (`git reset --soft` ثم commit بدون الملف). أضف الملف إلى `.gitignore` وارفع `.env.example` بأسماء المتغيرات فقط. ولا تضف `.gitleaksignore` أبدًا. |
| فحص الأسرار: `Shallow clone` | جلب الـ CI آخر commit فقط | `fetch-depth: 0` (في GitHub) أو `GIT_DEPTH: 0` (في GitLab) |
| فحص الأسرار يفشل بسبب تاريخ قديم في مستودع قائم | أسرار قديمة رُفعت منذ زمن | غيّرها، وسجّل ADR، ثم اضبط `SECRET_SCAN_FROM=<commit التبنّي>` في `.github/engineering-rules.env`. عندها يغطي الفحص الـ commits الأحدث فقط ويقول ذلك بوضوح. |
| فحص الوثائق: `code changed under "<glob>" without a change in: ...` | تغيّر الكود ولم تتغير وثائقه | حدّث إحدى الوثائق المذكورة في طلب الدمج نفسه. وإذا لم تتأثر أي وثيقة فأضف الوسم `no-docs-needed` مع سبب مكتوب. |
| فحص الوثائق: `CHANGELOG.md has no entry` | طلب `feat` أو `fix` بلا سطر في سجل التغييرات | أضف سطرًا تحت `Unreleased`. وعناوين النوع `chore` و`ci` و`test` معفاة. |
| فحص الوثائق: تنسيق Markdown | ملف Markdown تغيّر ويخالف قاعدة | أصلح الملف (الرسالة تسمّي القاعدة والسطر). والملفات القديمة لا تُفحص في النمطين `lite` و`standard`. |
| فحص الوثائق: وثيقة مطلوبة ناقصة | ملف من `required-docs.json` غير موجود | أنشئه، أو احذفه من القائمة بـ ADR. |
| بوابات السياسة: `currency code literal` أو `region code` أو `time-zone id` أو `dial prefix` أو `named place` | إعدادات العمل مكتوبة داخل الكود | انقل القيمة إلى الإعدادات (متغيرات البيئة أو جدول إعدادات). وإذا كان إنذارًا كاذبًا (اختبار أو بيانات أولية) فأضف نمط المسار إلى `.github/policy/country-literals.json`. |
| بوابات السياسة: `... is a prerelease` | اعتماد تجريبي (beta أو rc أو preview) | استخدم إصدارًا مستقرًا، أو اكتب ADR وأضف الحزمة إلى `.github/policy/prerelease-allow.json`. |
| انتهاء الأعلام | علم ميزة تجاوز تاريخ `expiresOn` | احذف العلم وكوده، أو مدّد التاريخ واكتب السبب. |
| حجم الطلب: `changes N lines, above 800` | طلب الدمج كبير جدًا | قسّمه. وأخرج البيانات المولَّدة أو الملصقة من التغيير. وإذا تعذّر التقسيم فأضف `pr-size-reason` واشرح في الوصف. |
| إعداد Renovate | الملف `renovate.json` غير صالح أو لا يرث الإعداد المشترك | شغّل `bash .github/scripts/renovate-config-check.sh`؛ والمدقق يسمّي المفتاح. |

## بوابات التقنيات (كل التقنيات)

| النتيجة | المعنى | الإصلاح |
|---|---|---|
| `deps` FAIL: no lockfile | تطبيق بلا ملف قفل | ارفعه (`package-lock.json` أو `Cargo.lock` أو `composer.lock` أو `Gemfile.lock` أو `pubspec.lock` أو `uv.lock`...). |
| `deps` FAIL: install failed | التثبيت المقفل لا يعمل | شغّل الأمر نفسه محليًا (الخرج يعرضه). غالبًا ملف القفل غير متوافق مع ملف البيان: أعد توليده وارفعه. |
| `test` SKIP: no tests | بوابة مطلوبة ليس لها ما تشغّله | أضف اختبارات، أو اضبط `STACK_REQUIRE` لحذف `test` بـ ADR. والمشروع بلا اختبارات يجب أن يقول ذلك. |
| `NOT RUN` | أداة أو شبكة ناقصة | ثبّت الأداة (الرسالة تسمّيها). في الـ CI أضف خطوة الإعداد؛ وعلى جهازك استخدم مدير الحزم. |
| `format` FAIL | الكود غير منسّق | شغّل المنسّق (`prettier --write` أو `gofmt -w` أو `dotnet format` أو `cargo fmt` أو `dart format .` أو `ruff format` أو `pint` أو `tofu fmt`). |
| `lint` FAIL | فاحص الكود أو المحلل وجد مشاكل | أصلحها. والقاعدة التي لا توافق عليها تُغيَّر في إعداد الأداة نفسها، في طلب دمج مراجَع. |
| `audit` FAIL | اعتماد فيه ثغرة معروفة | حدّثه. وإذا لم يوجد إصلاح فسجّل ADR فيه التخفيف، وأضف استثناء الثغرة في ملف الأداة نفسها. |
| `bundle-scan` FAIL (`Next.js`) | مضيف الخادم الخاص في حزمة العميل | انقل الاستدعاء خلف مسار على الخادم؛ وأبقِ المضيف في متغير للخادم فقط. |
| `secrets-files` FAIL (الموبايل) | ملف مفاتيح توقيع أو ملف اعتماد أو رابط `http://` مرفوع | أزله، وغيّر المفتاح، واستخدم مخزن أسرار. |
| `migrations` FAIL (`Django`) | تغيّر نموذج بلا ترحيل | `python manage.py makemigrations` ثم ارفع. |
| `mod-tidy` FAIL (`Go`) | الملفان `go.mod` أو `go.sum` غير مرتبين | `go mod tidy` ثم ارفع. |
| `pinned` FAIL (`Python`) | متطلب بلا `==` | ثبّته (`pip freeze` أو أداة قفل). |

## لوكيل الذكاء الاصطناعي

1. شغّل `bash .github/scripts/local-proof.sh --json` واقرأ `gates[].status`.
2. لكل `FAIL` شغّل تلك البوابة وحدها (`references/local-proof.md` يسرد الأوامر) واقرأ خرجها.
3. أصلح السبب. ولا تعدّل بوابة أو نمطًا أو وسم استثناء أو تثبيتات لتجعلها تنجح.
4. إذا احتاج الإصلاح قرارًا (اعتماد جديد، أو خروج عن قاعدة، أو طلب دمج أكبر) فاكتب سؤالًا مفتوحًا أو ADR وتوقف.
5. أعد التشغيل حتى يكون كل صف `PASS` (أو `NA`). والصق إثبات Markdown في طلب الدمج.
