# دليل تشغيلي: تغيير الأسرار والمفاتيح

> الحالة: Partial. املأ التفاصيل لمزوّديك، ثم غيّر الحالة إلى Verified.

متى تستخدمه: حسب جدول زمني، أو بعد أي تسريب، أو عندما يفشل فحص الأسرار. اكتشاف فحص الأسرار يمنع الدمج، ويُعالج بتغيير السر وليس بإضافته إلى قائمة التجاهل.

## الدورية

حدّد دوريتك واكتبها هنا، مثلًا: مفاتيح التوقيع والتشفير سنويًا مع فترة تداخل؛ ومفاتيح المزوّدين وواجهات البرمجة كل 90 يومًا وعند مغادرة أي شخص لديه وصول.

## الخطوات

1. اعتبر السر المسرّب مخترقًا. حدّد أين يُستخدم وافحص نشاطه عند المزوّد. عند وجود إساءة استخدام نشطة، ألغِه فورًا واتبع إجراءات الحوادث بدل انتظار نشر بديل اعتيادي.
2. أنشئ البديل في مخزن الأسرار، وليس في Git أو المحادثات أو الوثائق. غيّر أيضًا أي بيانات اعتماد مشتقة من السر المتأثر.
3. انشر البديل واختبره، ثم ألغِ القديم عند المزوّد وفق خطة الاستجابة للحادث. افحص السجلات بحثًا عن استخدام غير مصرح به.
4. أزل القيم الحساسة من مجلد العمل. الإلغاء لا يمحو تاريخ Git أو النسخ السابقة أو البيانات المشتقة؛ عالجها وفق سياسة المزوّد والمشروع.
5. شغّل فحص الأسرار مجددًا. الفحص الافتراضي يشمل التاريخ الكامل، ولذلك قد يظل السر القديم مكتشفًا بعد إلغائه. لا تضف قائمة تجاهل لإخفائه. إذا أُقرّ `SECRET_SCAN_FROM` لمعالجة تاريخ قديم، فسجّل تدوير الأسرار والحدود والتغطية المستثناة في ADR معتمد؛ هذا تضييق للنطاق لا تنظيف مكافئ للتاريخ.
6. سجّل تاريخ الحادث وسببه والإجراءات والأدلة غير الحساسة في طلب الدمج أو سجل الحادث، دون نسخ قيمة السر.

## التصعيد

مالك الخدمة المتأثرة، ثم مالك المشروع.
